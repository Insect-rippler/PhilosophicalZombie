# 事件系统重构：地点事件 → 每小时判定 + 子代理生成

状态：**设计稿，未实现**。整理完一起改，不再分批打补丁。

---

## 0. 一句话

删掉地点事件和地图节点。每小时掷一次骰，命中就拉一个子代理，看场景/状态/时间/世界观生成一件具体的事，写进 state。

---

## 1. 为什么要改（现有数据）

她最近 119 次带 location 的动作：

```
地图内      21 次（18%）
地图外      98 次（82%）
```

事件库里 50 个事件，29 个 `scope: location`，只挂 7 个节点：

```
workshop 5 · room 5 · market 4 · kitchen 4 · hall 4 · deck/edge 6
```

结果：**她在城外的整天，地点事件一次都没触发过**——矿坑、土路、城门口、草场，一个事件都没有。

另外两套名单不一致：

```
地图           甲板 主街 工坊区 厨房 她的房间 集市 地块边缘
timers.places  再加上 面包房 河沿 后巷
```

## 2. 判断

地图是**维护负担**，而且对角色没有意义：

- 地图不会推给角色（推了也是几十行节点，占上下文）
- 她走路靠记忆和常识，不靠邻接表
- 现实里人也不背地图，是“记得从这儿往西走一刻钟就是面包房”

**所以：地点退化成自由文本，路线交给向量记忆。**

---

## 3. 新模型

### 3.1 事件只有一个来源：整点判定

```
每小时整点触发一次判定（24 次/天）
判定先走代码，命中才调子代理
```

判定输入（都是现成的，不需要地图）：

```
小时             时段概率不同
睡着/醒着        睡着时概率低，且只允许「吵醒」类
距上次事件        冷却，默认 ≥3 小时
今天已发生几次    上限，默认 4 次
plan 是否有进行中 有任务时略高（世界在推进）
```

建议初值：

| 时段 | 醒着 | 睡着 |
|---|---:|---:|
| 08–22 | 6%/小时 | — |
| 22–08 | 2%/小时 | 1%/小时 |

期望：醒着一天约 1.5 次，睡着几乎不发生。全部走 `harness.events.*` 可调。

### 3.2 命中后：子代理生成

输入材料（控制在 1k token 内）：

```
当前时间 + 时段描述
当前地点（自由文本，如「奥格尼斯科/城外坡顶」）
她的状态（生理阶段、情绪、手上的事）
plan 的当前步骤
最近 3 轮对话的摘要（不是原文）
世界常识（lorebook 命中 2~3 条）
最近 24 小时已发生的事件标题（防重复）
```

输出（JSON）：

```json
{
  "title": "坡顶的风",
  "text": "风从北面压过来，草伏成一片；坡下有人赶着车往东去。",
  "kind": "ambient",
  "tags": ["风", "路人"],
  "wake": false
}
```

`kind` 三档，决定后续处理：

```
ambient   环境变化，不动数值
notice    她注意到什么，可能引出线索
wake      打断（有人敲门、喊她），睡着时也能发生
```

生成结果写进：

```
state 的一行「刚发生：…」      下一轮就能看到
events.json 的历史            冷却与防重复要靠它
```

失败处理：超时/解析失败就**静默跳过**，不重试、不阻塞 tick。

### 3.3 地图退役

```
places.json 的节点与 links    不再进入任何 prompt
body.map_lines()              删除
timers.render_environment()   只用 location 文本，不再查地点表
timers.places()               删除
activities.json               保留（那是「能做什么」，不是地图）
combat.py 的 load_world       只取敌人表，不碰地点
```

位置的事实来源只剩一个：`character.local`（自由文本）。

### 3.4 路线交给向量

新增语料类别 `route`（和锚点同一套嵌入）：

```
"从主街往西走一刻钟就是面包房，门口挂着铁皮招牌。"
"出北门沿土路走半个时辰到坡顶，坡底分岔，往东是草场，往北是矿坑。"
```

触发时机：

```
对话或 plan 提到 回家 / 去某地 / 迷路
    → recall 额外查一次 route 类
    → 命中就注入「你记得的路线」
```

冷启动：先手写 8~10 条常走路线；之后由 dream 从 session 里提炼她走过的新路线。

**这一步和锚点实验共用同一套东西**，先把 `lab/anchors` 的检索跑通，再决定是否并进 `recall.py`。

## 6. 测试计划（实验区，全能力）

| 编号 | 内容 | 看什么 |
|---|---|---|
| T1 | 200 天加速，只走判定不调子代理 | 每天事件数分布，是否接近设定 |
| T2 | 24 次真实生成 | 事件与地点/时间/状态是否一致，人工抽样 20 条 |
| T3 | 同一天连续生成 | 有没有重复标题/重复内容 |
| T4 | 问她“怎么回家” | route 语料能不能召回，召回的是不是对的 |

判据：

```
T1  日均 1~2 次，无连续两天 0 次，无单日 >6 次
T2  20 条里 ≥16 条读起来像「此刻可能发生的事」
T3  24 小时内标题不重复
T4  前 3 条里含正确路线
```

## 7. 开放问题

1. **睡着时能不能有事件**：现在设定是“只在 wake 类允许”，但睡眠刚修好，别轻易打断。建议先关掉，等睡眠数据稳定。
2. **事件要不要动数值**：先只叙事，不动数值。要动就单独设计 `effect`，别混在文本里。
3. **事件和 plan 冲突**：事件不改变 plan，只提供线索。
4. **旧 events.json 数据**：开发期直接弃用，不做迁移。
5. **子代理用哪个模型**：先用主模型（低温度），跑一段时间再考虑换小模型省钱。
