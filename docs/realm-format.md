## 现在的问题

**1. 标题层级不统一**

```
PERSONA    ## 人格 / ### 行为倾向 / #### 输赢之后
CHARACTER  ## 一、我是什么人 / ## 二、…
USER       ## 怎么认识的 / ## 我知道的
```

有的是编号章节，有的是无编号小节，`####` 只在个别地方出现。
dream 写入靠标题定位（`find_block`），层级不一致会定位不到。

**2. 写作规则混在设定里**

`ConsciousnessRealm/README.md` 里讲“每一节怎么写”，
但 md 文件本身没有字段说明——换一个人来填，不知道该写多长、写什么。

**3. 机器可读性为零**

```
想统计“她的价值观有几条” → 只能数 `- ` 开头的行
想确认“边界有没有配动作” → 只能人读
```

## 候选方向（都不定）

**A. 统一成五节卡**

```
# 身份
## 事实        （不可变）
## 判断        （会变，dream 可写）
## 边界        （分级 + 越界动作）
## 经历        （时间线）
## 一句话
```

机器按 `##` 定位，dream 只动「判断」与「经历」。

**B. 结构化字段 + 叙述**

```yaml
# front-matter
name: 薇薇安娜·德罗斯特
values: [不把善意当亏欠, 承诺要兑现, …]
boundaries:
  - level: 不可让
    what: 用诗换好处
    react: 只说不愿，不解释第二遍
```

正文再写叙述。优点是可校验，缺点是要维护 schema。

**C. 不改 md，只加一份字段表**

`ConsciousnessRealm/README.md` 里列出每节的字段与写法，
md 保持自由格式。成本最低，但机器仍然读不了。

## 待定问题

1. **空白卡要哪些字段**：这个没想清楚，格式定不下来（用户原话）。
2. **dream 与手写的边界**：哪些节允许自动改，哪些只读。
3. **格式与 UI**：识域页现在是纯文本编辑器，要不要按节分栏。
4. **迁移成本**：七份文件重排一次，历史记录里的引用（`find_block`）会失效。

## 结论

**先不做。** 等空白卡实验跑出“缺哪些字段”的结论，再回头定格式——
否则会先画一张没有内容的表格。
