# state 与 body 交还：让主代理自己判断「做不做得到」

状态：**设计稿，未实现**。和 `events-redesign.md` 一起改。

---

## 0. 一句话

把 body 的判定交还给主代理，省掉一回合一次的子请求；代价是要把 body 手里的情报写进 state，
不然她是“闭着眼睛做决定”。

---

## 1. 现在的情报差

同一份状态，两个代理看到的不一样：

| 信息 | 主代理（`full=False`） | body（`full=True`） |
|---|---|---|
| 时间 / 地点 / 穿着 | ✅ | ✅ |
| 生理数值与阶段 | ❌ 只在异常时出现 | ✅ 全部 |
| 正在做的事 | 只有 `semantic` 一句 | ✅ 含剩余时间 |
| 槽位上限 | ❌ | 规则内置 |
| 已结束的空槽 | ❌ | ❌（两边都没有） |

结果是：**她做决定时并不知道自己多累、手上还占着什么。** 现在这些都由 body 兜着，
所以每次都要多问一次模型。

---

## 2. 目标状态（主代理看到的 `<state>`）

```
当前时间：20:10（夜里，天黑了，人往回走）。
角色当前位置：奥格尼斯科/城外土路。
角色当前穿着：深棕工装、墨绿披风、束发。
身体：困意 38/100（正常）· 疲惫 65/200（正常）· 饱食 65/100 · 水分 56/100 · 健康 100/100
手上：
  [long]  她提灯带两人往坑口去（还剩 12 分钟，20:22 结束）
  [short] 空
  [event] 空
上限：short 5 分钟 · long 187 分钟 · event 463 分钟
刚发生：坡顶的风把灯吹得偏了一下（20:00）
```

字段说明：

| 行 | 内容 | 为什么需要 |
|---|---|---|
| 身体 | 数值 + 上限 + 阶段词 | 判断“我现在撑不撑得住” |
| 手上 | 每个槽一行，空槽写「空」 | 判断“能不能同时做” |
| 上限 | 三个槽的分钟数 | 判断“这件事要多久、放哪” |
| 刚发生 | 最近一次事件（来自事件重构） | 判断“有没有被打断” |



### 身体那行为什么要带上限

数值本身没有意义，模型会默认「100 就是满」，于是：

```
疲惫 65   → 以为「六成半，快到头了」   实际 200 满，还有余量
疲惫 150  → 以为「超出上限了」        实际才七成半
```

不写上界，她会按错误的刻度判断自己能不能撑住。所以必须写成 `65/200`。

当前各指标的量程（`body/metabolism.json` 的 `ranges`）：

| 指标 | 范围 | 满值意味着 |
|---|---|---|
| 困意 sleepiness | 0–100 | 再撑会昏过去 |
| 疲惫 fatigue | 0–200 | 撑不住（_body_block 会拒） |
| 饱食 satiety | 0–100 | 100 是吃撑，正常在 60~80 |
| 水分 hydration | 0–100 | 低于 40 开始拖累疲惫与困意 |
| 健康 health | 0–100 | 长期累积，短期不回满 |
| 情绪 emotion | 0–240 | 120 是平常 |

**空槽要显式写出来。** 现在她只能从“被拒”里知道有东西占着，等于用失败换信息。

## 3. 工具参数的变化

`active` 增加一个可选字段：

```json
{
  "description": "她提灯带两人往坑口去",
  "slot": "long",
  "minutes": 25,          // 新增：她自己估的时长
  "scene": "…",
  "force": false
}
```

规则：

```
minutes 不填   → 按 slot 的默认值（short 2 / long 30 / event 180）
minutes 超上限 → 直接拒，回执写清上限是多少
minutes 明显离谱（> 上限 × 1.0）→ 拒，让她改 slot
```

body 拿到 `minutes` 后**不再调模型**，只做三件事：

```
① 槽位是否被占（同槽未到期就拒，除非 force）
② 生理硬状态（撑不住时拒，沿用 _body_block）
③ 落账：建计时器、写 state、到点结算
```

---

## 4. 主代理的判断规则（写进 AGENT，两句话）

```
我想做：这件事要不要做、做多久。
我做得到：手上有没有空槽、身体撑不撑得住、上限够不够。
```

配套：

```
- 先看 state 的「手上」和「身体」，再决定递交什么。
- 三个槽互相独立：short 做小事、long 做手头上的活、event 交给一整天。
- 想打断手上的事才用 force；被拒不带 force 就等它到期。
- 估不准时长就填保守值，宁可短一点——短了可以再做一次。
```

## 8. 开放问题

1. **minutes 让谁估**：她自报 vs 按描述关键词查表。先让她自报，偏差大了再引入查表。
2. **event 槽要不要显示剩余**：一整天的事显示“还剩 6 小时”很怪，可能只显示“今天在做 X”。
3. **body 完全删还是留申诉**：先留 `appeal`，跑一段时间看有没有人用它。
4. **和事件重构的顺序**：先做事件（state 要加「刚发生」），再做交还——两次改同一处 state，分开会打两次补丁。
