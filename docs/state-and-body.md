# state 与 body 交还：让主代理自己判断「做不做得到」

状态：**设计稿，未实现**。和 `events-redesign.md` 一起改。

---

## 0. 一句话

把 body 的判定交还给主代理，省掉一回合一次的子请求；代价是要把 body 手里的情报写进 state，
不然她是“闭着眼睛做决定”。

---

## 1. 现在的情报差

同一份状态，两个代理看到的不一样：

| 信息 | 主代理（`full=False`） | body（`full=True`） |
|---|---|---|
| 时间 / 地点 / 穿着 | ✅ | ✅ |
| 生理数值与阶段 | ❌ 只在异常时出现 | ✅ 全部 |
| 正在做的事 | 只有 `semantic` 一句 | ✅ 含剩余时间 |
| 槽位上限 | ❌ | 规则内置 |
| 已结束的空槽 | ❌ | ❌（两边都没有） |

结果是：**她做决定时并不知道自己多累、手上还占着什么。** 现在这些都由 body 兜着，
所以每次都要多问一次模型。

---

## 2. 目标状态（主代理看到的 `<state>`）

```
当前时间：20:10:00（夜里）。
距上一次行动已过去 00:12:40。
角色当前位置：荒野/营地（风险 0：安全）。
角色当前穿着：深棕工装、墨绿披风、束发。
[short] 空
[long] 正在做：我在墙根坐下歇一阵（已过 00:20:00 / 共 01:00:00，进度 33%）
[event] 空
刚刚发生：我把水囊灌满，系回行囊侧袋（完成）
```

身体与情绪只在阶段有话说时出现；环境、风险、常见人物不写进 state，风险只跟在当前位置后面。

字段说明：

| 行 | 内容 | 为什么需要 |
|---|---|---|
| 身体 | 数值 + 上限 + 阶段词 | 判断“我现在撑不撑得住” |
| 手上 | 每个槽一行，空槽写「空」 | 判断“能不能同时做” |
| 上限 | 三个槽的分钟数 | 判断“这件事要多久、放哪” |
| 刚发生 | 最近一次事件（来自事件重构） | 判断“有没有被打断” |



### 身体那行为什么要带上限

数值本身没有意义，模型会默认「100 就是满」，于是：

```
疲惫 65   → 以为「六成半，快到头了」   实际 200 满，还有余量
疲惫 150  → 以为「超出上限了」        实际才七成半
```

不写上界，她会按错误的刻度判断自己能不能撑住。所以必须写成 `65/200`。

当前各指标的量程（`body/metabolism.json` 的 `ranges`）：

| 指标 | 范围 | 满值意味着 |
|---|---|---|
| 困意 sleepiness | 0–100 | 再撑会昏过去 |
| 疲惫 fatigue | 0–200 | 撑不住（_body_block 会拒） |
| 饱食 satiety | 0–100 | 100 是吃撑，正常在 60~80 |
| 水分 hydration | 0–100 | 低于 40 开始拖累疲惫与困意 |
| 健康 health | 0–100 | 长期累积，短期不回满 |
| 情绪 emotion | 0–240 | 120 是平常 |

**空槽要显式写出来。** 现在她只能从“被拒”里知道有东西占着，等于用失败换信息。

## 3. 工具参数的变化

`active` 的参数：

```json
{
  "short": "我提灯带两人往坑口去",
  "seconds": 1500,
  "scene": "…",
  "location": "奥格尼斯科/矿坑口"
}
```

规则：

```
short / long / event 三选一，一条 message 只调一次 active
seconds 必填（sleep 除外），主代理自己估整秒
short 带 location：地点必须已存在且与当前相邻；不存在先 map create，不相邻先 map query
short 的 location 可省略，省略 = 当前位置；long / event 必须填 location，写到点应在的位置；不走地图，只做到点校验
槽位占着才拒；身体状态不再拒绝普通 active
```

body 在后台补奖励与到点文本；时长以主代理填的 seconds 为准，不再由 body 改写。
## 4. 主代理的判断规则（写进 AGENT，两句话）

```
我想做：这件事要不要做、做多久。
我做得到：手上有没有空槽、身体撑不撑得住、上限够不够。
```

配套：

```
- 先看 state 的「手上」和「身体」，再决定递交什么。
- 三个槽互相独立：short 做小事、long 做手头上的活、event 交给一整天。
- 想打断手上的事才用 force；被拒不带 force 就等它到期。
- 估不准时长就填保守值，宁可短一点——短了可以再做一次。
```

## 8. 开放问题

1. **seconds 让谁估**：已确定由主代理自报；body 不再改时长。
2. **event 槽要不要显示剩余**：一整天的事显示“还剩 6 小时”很怪，可能只显示“今天在做 X”。
3. **body 完全删还是留申诉**：先留 `appeal`，跑一段时间看有没有人用它。
4. **和事件重构的顺序**：先做事件（state 要加「刚发生」），再做交还——两次改同一处 state，分开会打两次补丁。

## 9. 交还方案（保留，暂不实施）

日期：2026-11-11。决定：**继续用 body 模型，准确性优先**；方案先记在这里，以后合并。

### 9.1 类别参数

`active` 增加 `kind`：

```
slot   快慢：short / long / event     （决定占哪个槽）
kind   性质：eat / drink / rest / work / travel / treat / sleep / other
```

### 9.2 数值仍由模型给，代码卡区间

`body/effects.json` 给每个 kind 定每分钟区间；模型报的 reward 按分钟折算后：

```
区间内      受理
超区间      钳到边界，回执注明「已按 <kind> 上限调整」
kind 缺失   按关键词猜，猜不出按 work
对不上      记 WARN，不拒绝
```

### 9.3 回执与到点文本

```
回执      代码模板生成
到点文本  用她自己给的 line / scene，不再让 body 写「到点后的一句话」
```

### 9.4 为什么先不做

```
数值靠模型的判断力，目前比关键词表准
省一次请求的价值 < 数值失真的代价
等类别稳定、日志里能看出误判率，再切
```

### 9.5 已完成的隔离

body 已按卡隔离：每张卡 `realm/body/{rule.md, judge.json, metabolism.json}`，
`paths.realm()` 优先读卡里的，缺文件回落到全局。
