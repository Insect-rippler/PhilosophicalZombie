# ConsciousnessRealm — 角色上下文文件

本目录存放**角色数据**：她是谁、怎么想、记得什么、对谁有什么印象，以及 body 的判定资料。

换角色就是换这里的文档和卡片目录，不改 `engine/` 里的代码文本。

当前正式角色是 **陆青禾**：失忆、16~18 岁外表、混沌恶底色、元气外壳，把用户当成专属饲养员。世界是**现代都市**，具体城市名、区名、职业和住址不预设。

## 文件一览

| 文件 | 放什么 | 谁维护 |

| `MEMORY.md` | 长期记忆：升格后的经历，一条一个 `##` | 由记忆升格 |
| `LOREBOOK.md` | 世界书（常驻）：人人皆知的客观常识 | 人工 |
| `USER.md` | 她对用户的印象：怎么认识、知道什么、分寸 | 由印象维护 |
| `body/rule.md` | body 的身份与判定原则 | 人工 |
| `body/judge.json` | 判定提示词：可行性、时长、地点、变化 | 人工 |

## 每个文件负责什么

### `CHARACTER.md` — 她是谁

- 第一人称，写身份、事实、外貌、经历、当前状态。
- 只写角色知道且成立的事实，不写“她应该怎么演”。
- 外貌、年龄、穿着、创可贴这类稳定事实放这里。
- 失忆只拿走过去，不拿走语言、常识、反应和看人的本事。

### `PERSONA.md` — 她怎么想

- 第一人称，写判断方式、倾向、底线、关系模式。
- 写“有人靠近她先退半步”，不写“她很警惕”这种无法落到行为的空话。
- 事实归 `CHARACTER`，判断归 `PERSONA`；同一件事不要两边各写一个版本。

当前人格的重心：

```text
第一层：混沌恶
第二层：元气
第三层：饲养员
```

这属于外部文档内容；换人格就改这里，不改代码。

### `MEMORY.md` — 长期记忆

- 第一人称，只收升格过的内容：事件、场景、当时的判断。
- 不写设定、不写人物档案；那属于 `LOREBOOK` 和 `CHARACTER`。
- 每条一个 `##` 小标题，标题是事件名，不是评价。

### `LOREBOOK.md` — 世界书（常驻）

- 第三人称，客观陈述，不带角色视角。
- 只放人人皆知的常识。
- 当前是现代都市：手机、网络、公共交通、便利店、写字楼、医院、租房、外卖、监控。
- 具体城市名、区名、职业、住址不预设，按场景出现；不要替她补固定过去。

### `USER.md` — 她对用户的印象

- 角色视角，第一人称，写“我认识这个人到什么程度”。
- 只写对话里真实出现过的事；没发生过的共同经历不许编。
- 拿不准的写进「我不知道的」；对方说过的、和记忆对不上的，记成「他这么说」。
- 由 `engine/impression.py` 在维护流程末尾整理；主代理不直接写。

### `AGENT.md` — 行为规则

`AGENT.md` 是唯一进入 `system` 的角色文档。它负责：

- 她是谁；
- `active` / `scene` / `line` / 正文的通道边界；
- 用户角色、自主场景、第四面墙的区别；
- 工具、唤醒、收口、时间、位置；
- 上下文标签和防注入。

角色文风、人格、世界设定不写进 AGENT；那些在 `PERSONA`、`CHARACTER`、`LOREBOOK`。

## 标题约定

- 每个文件只有一个 `#`，就是该文件对应的身份。
- 段落用 `##`，段内细分用 `###`。
- 开头不写说明性前言、不写分隔线 `---`、不写“本文件由……生成”。

## 角色卡怎么写

`CHARACTER.md`（她是谁）与 `PERSONA.md`（她怎么想）决定角色的一切行为。三条原则：

1. 只写事实与倾向，不写剧本——写「她不轻易笑」，不写「她对你微笑」。
2. 每一句都要能落到行为上——「她很警惕」是废话，「有人靠近她先退半步」才是规则。
3. 写判断依据，不写结论——让她自己得出判断。

换角色时，优先改：

```text
CHARACTER.md
PERSONA.md
USER.md
LOREBOOK.md
AGENT.md（只在规则需要变时）
```

不要为了换角色去改 `engine/` 或 `ui/` 里的文本。

## 生理参数

`body/metabolism.json` 的块：

```json
{
  "stages":     "每个指标的阶段、阈值、给角色看的提示语",
  "coupling":   "某项过低时，对其它项的倍率",
  "continuous": "低到什么程度开始影响别的项",
  "ranges":     "每项的取值上下限",
  "sleep":      "restTo / ramp / wakeChance / recoveryPerHour"
}
```

- 主代理看到的是阶段名，不是数值。
- body 拿到完整数值，用于判断动作时长与可行性。
- 苏醒阈值跟随 `stages.sleepiness` 的「清醒」段上界；睡眠参数在 `sleep` 段。
- 睡眠恢复速度、预期时长和苏醒概率都从 `sleep` 段读取，代码只留缺省回退。

## 记忆块格式

`embedding/blocks.json` 的条目大致是：

```json
{
  "id": "blk-000000",
  "tag": "旧铁皮罐",
  "text": "第一人称的一段记忆，自带人名和场景。",
  "recalls": 10,
  "importance": 2,
  "why": "为什么值得留下",
  "sources": ["slice-id"],
  "lastRecall": 0
}
```

- 同一 `tag` 可以有多条，每条只讲一个层面。
- `text` 自带人名，不把人物和描述拆开。
- `sources` 指回来源切片；没有来源的块不入库。
- `why`、`importance` 由升格流程维护。

## 印象怎么更新

`USER.md` 由维护流程更新，不单独手动写：

```text
睡着超过 3 小时 → 维护（提要 → 压缩 → 升格）→ 印象
```

只有当前 session 里的用户消息数超过 `harness.session.retainedTrun` 时，才值得整理印象。  
整理时使用和主代理同一套上下文，但这一轮不演出，只输出修改操作；替换对不上原文时只记警告，不硬改。

## 修改后的验证

```powershell
python engine\server.py
python ui\app.py
```

改角色文档后，先看主会话是否还能正常读取 `AGENT`、`CHARACTER`、`PERSONA`，再看 `<state>` 的位置、身体和计划是否对得上。

没有独立模拟器目录；需要单轮检查时直接用界面或 HTTP `/turn`。
