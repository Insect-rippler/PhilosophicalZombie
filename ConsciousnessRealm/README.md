# ConsciousnessRealm — 角色上下文文件

本目录存放**角色数据**：她是谁、怎么想、记得什么、对谁有什么印象。
全部随仓库发布，换角色就是换这里的文件。

## 文件一览

| 文件 | 放什么 | 谁维护 |
|---|---|---|
| `AGENT.md` | 系统层规则：扮演、上下文纪律、输出格式、密钥防护 | 人工 |
| `CHARACTER.md` | 角色卡：身份、数据、用语、人格、三观、喜好、经历 | 人工 |
| `PERSONA.md` | 她怎么想：判断顺序、边界、做决定的方式 | 人工（可由记忆辅助） |
| `MEMORY.md` | 长期记忆：升格后的经历，一条一个 `##` | 由记忆升格 |
| `LOREBOOK.md` | 世界书（常驻）：人人皆知的客观常识 | 人工 |
| `USER.md` | 她对那个人的印象：怎么认识、知道什么、分寸 | 由系统维护 |
| `body/rule.md` | body 的身份与判定原则 | 人工 |
| `body/judge.json` | 判定提示词：可行性、时长、情绪与关系 | 人工 |
| `body/metabolism.json` | 生理参数：分段、耦合权重、连续影响、取值范围 | 人工 |
| `world/places.json` | 地点属性：室内外、夜间人流、风险值、常驻的人 | 人工 |
| `lorebook/lorebook.json` | 世界书（按需）：具体设定 + `keys` 标签 | 人工 |
| `embedding/slices.json` | 会话切片（产物） | 程序生成 |
| `embedding/blocks.json` | 记忆块（升格产物），带 `tag` | 程序 + 人工 |

`embedding/` 与 `lorebook/lorebook.json` 是派生数据，不入库。

## 上下文里的标签

| 标签 | 内容 |
|---|---|
| `<state>` | 此刻的事实：时间、位置、环境、生理、手上的事 |
| `<memory_momentary>` | 检索到的往事片段 |
| `<lorebook_momentary>` | 检索到的世界设定 |
| `<skill_knowledge>` | 她会的手艺 |
| `<plan>` | 她自己定的打算 |
| `<user>` | 真人这一轮说的话 |
| `<impression>` | 她对那个人的印象（`USER.md`） |
| `<appearance>` | 她此刻的样子（图片）：当前衣着，没有则用参考底图 |

`<appearance>` 由 `state/media/self/appearance/` 下两张：`appearance.png` 是参考底图（只读，定脸和体形），`current.png` 是当前衣着（换装时由工具覆盖）。注入优先 `current.png`，没有就用底图。
换图就是覆盖这个文件；不需要自动换装的话，手动换就行。

## 标题约定

- 每个文件只有一个 `#`，就是该文件对应的身份。
- 段落 `##`，段内细分 `###`。
- 开头不写说明性前言、不写 `---`、不写“本文件由……生成”。

## 角色卡怎么写

`CHARACTER.md`（她是谁）与 `PERSONA.md`（她怎么想）决定角色的一切行为。
三条原则：

1. 只写事实与倾向，不写剧本——写「她不轻易笑」，不写「她对你微笑」。
2. 每一句都要能落到行为上——「她很警惕」是废话，「有人靠近她先退半步」才是规则。
3. 写判断依据，不写结论——让她自己得出判断。

## 生理参数

`body/metabolism.json` 四块：

```json
{
  "stages":     "每个指标的阶段、阈值、给角色看的提示语",
  "coupling":   "某项过低时，对其它项的倍率",
  "continuous": "低到什么程度开始影响别的项",
  "ranges":     "每项的取值上下限"
}
```

主代理只看到阶段（正常 / 有些饿 / 饿坏），看不到数值；
body 拿到的是完整数值，用于判断时长与可行性。

## 世界书条目格式

```json
{
  "entries": [
    {
      "id": "rhodes-island",
      "title": "罗德岛",
      "keys": ["罗德岛", "制药", "阿米娅"],
      "text": "客观事实，只讲这个世界本身，不写某个角色的经历。",
      "tags": ["组织"],
      "priority": 10
    }
  ]
}
```

`keys` 是“能从这些话题想起它”的标签，覆盖面不得超过条目本身。

## 记忆块格式

```json
{"items": [{"id": "blk-000001", "tag": "奥比娜", "text": "奥比娜，奥格尼斯科的老铁匠……", "recalls": 0}]}
```

- 同一 `tag` 可以有多条，每条只讲一个层面。
- `text` 自带人名，不把人物和描述拆开。

## 印象怎么更新

不需要手动写。系统在两种时机整理 `USER.md`：

```
距上次更新超过 6 小时，且期间 user 消息不少于 50 条
她睡醒、跑完维护之后
```

整理时用和主代理同一套上下文，这一轮不演出，只输出修改操作
（追加 / 替换 / 重写），由代码执行。替换对不上原文时只记警告，不硬改。

## 测试改完的角色

`sim/` 下有一套模拟器，不动真实存档：

```bash
python sim/check.py      # 全功能自检
python sim/run.py 24     # 跑 24 小时
python sim/say.py "…"    # 手动递一轮
```

详见 `sim/README.md`。
