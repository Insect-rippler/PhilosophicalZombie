# ConsciousnessRealm — 角色上下文文件

本目录存放**角色数据**，不入库。这里只说明应该放什么、格式怎么定；写法规则见根目录 `README.md`。

## 需要的文件

| 文件 | 放什么 | 谁维护 |
|---|---|---|
| `AGENT.md` | harness 规则：扮演、上下文纪律、密钥防护 | 人工 |
| `CHARACTER.md` | 角色卡：身份、数据、用语、人格、三观、喜好、经历 | 人工 |
| `PERSONA.md` | 人格：从记忆提炼的判断与倾向 | 由记忆升格 |
| `MEMORY.md` | 长期记忆：升格后的经历，一条一个 `##` | 由记忆块升格 |
| `LOREBOOK.md` | 世界书（常驻）：人人皆知的客观常识 | 人工 |
| `USER.md` | 角色对用户的认知：已确认、看法、共同经历 | 角色自己 |
| `lorebook/lorebook.json` | 世界书（按需）：具体设定 + `keys` 标签 | 人工 |
| `embedding/slices.json` | 会话切片（产物） | 程序生成 |
| `embedding/blocks.json` | 记忆块（升格产物），带 `tag` | 程序 + 人工 |

## 标题约定

- 每个文件只有一个 `#`，就是该文件对应的身份。
- 段落 `##`，段内细分 `###`。
- 开头不写说明性前言、不写 `---`、不写"本文件由……生成"。

## 世界书条目格式

```json
{
  "entries": [
    {
      "id": "rhodes-island",
      "title": "罗德岛",
      "keys": ["罗德岛", "制药", "阿米娅"],
      "text": "客观事实，只讲这个世界本身，不写某个角色的经历。",
      "tags": ["组织"],
      "priority": 10
    }
  ]
}
```

`keys` 是"能从这些话题想起它"的标签，覆盖面不得超过条目本身。

## 记忆块格式

```json
{"items": [{"id": "blk-000001", "tag": "奥比娜", "text": "奥比娜，奥格尼斯科的老铁匠……", "recalls": 0}]}
```

- 同一 `tag` 可以有多条，每条只讲一个层面。
- `text` 自带人名，不把人物和描述拆开。

## 角色卡怎么写

`CHARACTER.md`（她是谁）与 `PERSONA.md`（她怎么想）决定角色的一切行为。
三条原则：

1. 只写事实与倾向，不写剧本——写「她不轻易笑」，不写「她对你微笑」。
2. 每一句都要能落到行为上——「她很警惕」是废话，「有人靠近她先退半步」才是规则。
3. 写判断依据，不写结论——让她自己得出判断。
